<h2>Implementing an algorithm by modelling an FSM in an HDL</h2>

<p>We are going to use Verilog for this project. Any Verilog compiler and simulator should do. Xilinx and ModelSim are really good tools. But since I'm a *nix guy, I'm going to use Icarus Verilog to compile code and gtkwave to view the signal timing diagrams. <h2>Concepts</h2>

<p>In a complex digital system, the hardware is typically partitioned into two parts:</p>

<p><strong>Data Path</strong> consists of the functional units where all computations are carried out. Typically consists of registers, multiplexers, bus, adders, multipliers, counters and other functional blocks.</p>

<p><strong>Control Path</strong> implements a finite-state machine and provides control signals to the data path in proper sequence. In response to the control signals, various operations are carried out by the data path. Also, it takes inputs from the data path regarding various status information.</p>

<p>The state transition is controlled by control path or control unit or controller. The control unit (CU) sends all the signals necessary to trigger any operation in the data path. The data path consists of elements that process data and addresses. Usually there's also a clock signal and a data bus that go to both data path and control path. By specifying a particular sequence of operations, the control unit can implement a given algorithm.</p>

<h2>The problem to model</h2>

<h3>Multiplication by repeated addition</h3>

<pre><code>Algorithm: Multiply (a, b)
Step 1.   Get the values for a and b.
Step 2.   If (either a = 0 or b = 0) then
Step 3.       Set the value of the product to be 0
Step 4.   Else
Step 5.       Set the value of product to 0
Step 6.       While (b > 0)
Step 7.           Set the value of product to (product + a)
Step 8.           Set the value of b to (b - 1)
Step 9.       End while loop
Step 10.  End if
Step 11.  Print the value of product
Step 12.  Stop</code></pre>

<h2>Data path and control path design</h2>

<p>Our data path consists of three registers: A, B and P, one adder unit and one comparator unit. Moreover, these components are connected to data bus (through which input data comes) and different incoming signals (LdA, LdP, clrP, LdB, decB, clk) from control unit and clock frequency generator. Also, there is an outgoing status signal eqz. Moreover there are 3 wires: wire x connecting register A to adder, wire y connecting register P to adder and wire z that puts the sum of A and P back into P.</p>

<img src="https://github.com/axayjha/axayjha.github.io/raw/master/img/mul_system/data_path.png" alt="Data path design diagram">

<p>If we see the overall system, 1 data line (data_in) and 2 signals (start and clk) are going in and one status signal (done) is coming out. These 4 parameters are what we will use in test bench also to test our design. Other than that, 5 control signals are going to data path unit from control unit apart from a clock signal. And data path is returning eqz (equal to zero) status signal from comparator to CU.</p>

<img src="https://github.com/axayjha/axayjha.github.io/raw/master/img/mul_system/mul_system.png" alt="Overall multiplication system diagram">

<p>The control unit and its signals help specify the transitions to different states for different operations and conditions. The following diagram shows how the algorithm flow chart is mapped to a finite state diagram:</p>
